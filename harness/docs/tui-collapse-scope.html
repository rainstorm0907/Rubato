A안 — 도구 전체에 적용

"다 같게" 하려면 기준이 하나 필요합니다. 도구 이름을 나열하는 대신 규칙 하나로 가르는 안입니다.

기준 — 워크스페이스를 바꾸는가
안 바꾸면(조회) 뭉치고, 바꾸거나 실행하면 단독으로 남깁니다. 새 도구가 생겨도 이 기준으로 자동 분류돼서 목록을 다시 손댈 필요가 없습니다.

하나 애매한 것: bash

git status·ls -la 같은 조회성 명령과 npm run build 는 같은 bash 도구입니다. 이름만으론 안 갈립니다.

조회성
]8;;senpi-action:5\ $ git status                                                                               ]8;;\
실행
]8;;senpi-action:6\ $ npm run build                                                                            ]8;;\

셋 중 하나를 골라야 합니다 — ① bash는 전부 단독(안전), ② 명령어 첫 낱말로 판단(git status·cat·ls 등은 뭉침), ③ 성공했고 출력이 짧으면 뭉침.
