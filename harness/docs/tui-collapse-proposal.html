도구 출력 접힘 — 수정안

현재 동작을 코드에서 실측한 결과 + 노이즈를 더 줄이는 선택지. 고르시면 그대로 구현합니다.

1. 먼저, 지금 코드는 이미 접고 있습니다

커밋 f26e229(오늘 03:10)이 들어간 뒤 도구는 접히면 1줄입니다. 실제로 컴포넌트를 띄워 렌더링해본 결과가 아래입니다 — 추측이 아니라 측정값입니다.

ls harness $ npm run build read src/index.ts grep /TODO/ in src write out.ts

에러일 때만 꼬리 1줄이 붙어 2줄이 됩니다.

$ npm test expected 1 got 2
그런데 ls 원문이 다 보이셨다면 — 지금 세션(03:27 시작)은 수정이 들어간 뒤에 떴으니 코드는 최신입니다. 남은 원인은 둘 중 하나입니다.
① ctrl+o로 전체 펼침이 켜져 있음(Tool output: expanded 상태가 유지됨). ② --verbose로 실행 — 이 플래그는 접힘을 통째로 무력화합니다.
아래 4번이 이 둘을 막는 안입니다.

2. 그래도 남는 노이즈

1줄로 접혀도 줄 수 자체는 도구 하나당 하나씩 계속 쌓입니다. ls 세 번, read 다섯 번이면 화면에 여덟 줄이 남습니다. 내용은 없고 자리만 차지합니다.

지금 — 도구마다 1줄

ls harness ls harness/prompts read harness/build.sh read harness/README.md grep /collapse/ in src $ bun test 이제 결과를 말씀드리면...

제안 — 조용한 도구는 뭉침

⋯ 탐색 5개 (ls·read·grep) $ bun test ✓ 12 pass 이제 결과를 말씀드리면...

3. 선택지

A안 — 읽기 전용 도구는 한 줄로 뭉치기추천

ls·read·grep·find처럼 아무것도 바꾸지 않는 도구가 연달아 나오면 ⋯ 탐색 5개 한 줄로 접습니다. 클릭하면 펼쳐집니다.

쓰기·실행(edit·write·bash)은 뭉치지 않습니다 — 뭘 바꿨는지는 보여야 하니까요.

B안 — 성공한 도구는 아예 숨기기

성공하면 화면에서 지웁니다. 에러만 남습니다. 가장 조용하지만, 제가 뭘 하고 있는지 안 보입니다.

$ npm test expected 1 got 2

C안 — 지금 유지, 뭉치기만 추가 안 함

도구당 1줄 그대로. 대신 4번(펼침 고정 방지)만 고칩니다.

4. 어느 안이든 같이 고칠 것

문제고칠 내용
ctrl+o 펼침이 세션 내내 유지됨 한 번 펼치면 새 도구까지 전부 펼쳐진 채로 남습니다. 턴이 끝나면 자동으로 접힘으로 되돌립니다.
--verbose가 접힘을 무력화 지금은 verbose면 무조건 펼침입니다. 이 둘을 분리해 verbose여도 접힘은 유지합니다.
펼칠 단서가 없음 접힌 줄 끝에 +18줄처럼 숨은 분량을 표시합니다.

5. 늘 펼쳐두는 것

todo와 task는 접으면 남는 게 없어서 지금도 항상 펼칩니다. 그대로 둡니다. 에러는 어느 안에서도 항상 보입니다.
