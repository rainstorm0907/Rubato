# omo 상속 에이전트 — 검토용

rubato-pi 는 Senpi 엔진 위에 얹혀 있고, Senpi 는 `omo-ai` 플러그인을 들고 온다.
그 플러그인이 subagent 넷을 정의한다 — 우리가 만든 것이 아니다.

2026-08-22 기준으로 **넷 다 껐다**. 무엇을 도로 켤지는 이 문서를 읽고 고르면 된다.

```
harness/rubato-pi/src/defaults.mjs   DISABLED_AGENT_NAMES
harness/rubato-pi/src/omo-config.mjs 이 목록을 { disable: true } 로 바꿔 Senpi 에 넘긴다
```

출처: `omo-ai@5.0.0-beta.15`, `plugin/extensions/omo.js` 안의 정의 배열.
프롬프트 전문은 `docs/omo-agents/<이름>.prompt.md` 에 그대로 떠 놓았다.

## 왜 껐나

셋이 겹쳤다.

1. **모델 라우팅이 우리한테 안 닿는다.** `~/.omo/omo.jsonc` 가 이 넷을 `xai/grok-4.6` 등으로
   보내지만 그 파일은 omo 본체(`~/.omo/agent`) 설정이다. rubato-pi 의
   `loadRubatoPiOmoConfig()` 는 그 파일을 읽지 않는다. 그래서 모델을 명시하지 않고 띄우면
   무엇으로 도는지 아무도 모른다.
2. **도구 표면에는 우리 것처럼 보인다.** 라우팅이 없는데 목록에는 뜬다. 실제로 이 세션에서
   리뷰어를 `explore` 로 띄웠다가 어긋난 모델 id 로 401 을 맞았다.
3. **역할이 우리 자리 구분과 안 맞는다.** 우리는 lead / teammate 둘로 자리를 갈랐는데,
   이 넷은 omo 의 ULW 계획 워크플로(metis → 계획 → momus 검수)를 전제한다.

끄는 것은 되돌릴 수 있다. 목록에서 이름 하나 빼면 그 에이전트만 돌아온다.

## 넷의 공통점

- 전부 `mode: subagent`, `executionMode: in-process`.
- **전부 읽기 전용.** 툴 세트가 넷 다 글자까지 같다:
  `read, find, grep, ls, bash, lsp_diagnostics, lsp_goto_definition, lsp_find_references, lsp_symbols`
- 여기의 `bash` 는 셸이 아니다. `{ program, args }` 형태만 받는 브로커이고 `gh` 와 `curl` 의
  읽기 요청만 통과시킨다. 파이프, 리다이렉트, clone, 쓰기 메서드는 거부된다.
- **모델이 정의에 없다.** `model: null` 이라 부르는 쪽이 정하거나, 안 정하면 호스트 기본값이다.
  이것이 1번 문제의 뿌리다.

## explore — 코드베이스 검색

프롬프트 2,675자. `docs/omo-agents/explore.prompt.md`

"X 는 어디 있나", "Y 를 담은 파일은", "Z 하는 코드 찾아라"에 답하는 자리다.
자기 설명으로는 "codebase search specialist".

요구하는 것:

- 검색 전에 `<analysis>` 태그로 의도 분석 — 문자 그대로의 요청, 진짜 필요, 성공의 모습.
- 첫 행동에서 **툴 3개 이상 동시 발사**. 순차는 앞 결과가 필요할 때만.
- `<results>` 안에 `<files>` / `<answer>` / `<next_steps>` 구조로 끝내기.
- 경로는 전부 절대경로. 상대경로가 하나라도 있으면 실패로 규정한다.

검토 포인트:

- 출력 형식이 강하다. 우리 teammate 자리는 "결과 파일이 전부"라고만 하지 태그 구조를
  강제하지 않는다. 둘을 같이 쓰면 자식이 어느 형식을 따를지 갈린다.
- "Failure Conditions" 절이 부정형 목록이다. 프롬프팅랩 기준으로는 긍정형 대안이 붙어야 한다.
- 반면 병렬 발사와 절대경로 요구는 실제로 값이 있다. 우리 프롬프트에 없는 것이다.

## librarian — 외부 저장소·공식 문서 조사

프롬프트 3,770자. `docs/omo-agents/librarian.prompt.md`

원격 코드와 공식 문서를 permalink 로 물어오는 자리. 로컬이 아니라 바깥을 본다.

요구하는 것:

- 요청을 넷으로 분류 — 개념 / 구현 / 맥락 / 종합.
- 커밋 SHA 를 먼저 잡고 `https://github.com/owner/repo/blob/<sha>/path#L10-L20` 형태의
  불변 링크를 만든다.
- 모든 실질 주장에 링크 + 근거 + 연결 설명. 추론과 버전 불확실성은 표시.
- permalink, SHA, 라인 범위, 인용을 **지어내지 말 것**.
- "현재 연도는 2026" 이 프롬프트에 박혀 있다.

검토 포인트:

- 이 자리가 넷 중 제일 독립적이다. 우리 하네스에 대응물이 없다. 웹 조사를 우리는
  `web_search` / `webfetch` 로 직접 하는데, 그건 계약이 없다.
- 연도가 하드코딩이라 내년에는 낡는다. 켤 거면 이 줄은 봐야 한다.
- `gh` 인증이 이 브로커를 통과하는지는 확인 안 했다. 켜기 전에 실제 호출 한 번 필요하다.

## metis — 계획 전 상담

프롬프트 11,212자. 넷 중 가장 길다. `docs/omo-agents/metis.prompt.md`

계획을 세우기 **전에** 요청을 뜯어 숨은 의도와 모호함을 찾는 자리.

구조:

- PHASE 0 에서 의도를 6종으로 분류 — 리팩터링 / 신규 구축 / 중간 규모 / 협업 / 아키텍처 / 조사.
- 분류마다 다른 질문 세트와 "Directives for the Planner" (MUST / MUST NOT).
- "AI-Slop Patterns" 절 — 범위 부풀리기, 성급한 추상화, 과잉 검증, 문서 남발을 잡아낸다.
- QA 기준을 **에이전트가 실행 가능한 명령**으로 쓰라고 강하게 요구한다.
  "사용자가 수동으로 확인" 류를 금지한다.

검토 포인트:

- 11K 는 우리 lead 프롬프트(12K)에 맞먹는다. 자식 하나에 이만큼 싣는 게 맞는지가 판단거리다.
- ULW 계획 워크플로 전제가 곳곳에 박혀 있다 — `architect` 카테고리에 위임하라는 지시가 있는데
  우리는 그 카테고리를 이미 껐다(`DISABLED_CATEGORY_NAMES`). 켜면 없는 곳을 가리킨다.
- 반대로 "AI-Slop Patterns" 와 "프로즈 산출물은 grep 으로 검수하지 마라"는 값이 있다.
  에이전트를 켜는 대신 그 문단만 우리 쪽으로 가져오는 선택지도 있다.

## momus — 계획 검수

프롬프트 6,562자. `docs/omo-agents/momus.prompt.md`

작성된 계획서가 실행 가능한지만 본다. `[OKAY]` 또는 `[REJECT]` 하나를 낸다.

요구하는 것:

- 입력에서 `.omo/plans/*.md` 경로를 정확히 하나 뽑는다. 0개나 2개 이상이면 거부.
- 참조된 파일이 실제로 있고 주장한 내용을 담는지 확인.
- **승인 편향** — 애매하면 승인. "80% 명확하면 충분하다".
- 거부는 진짜 막힌 것만. 최대 3개까지만 나열.
- 접근이 최적인지, 더 나은 방법이 있는지는 **보지 않는다**고 명시.

검토 포인트:

- 우리 워크플로에 `.omo/plans/*.md` 가 없다. 이 자리는 그 파일이 있어야 돌아간다.
  하네스 쪽에서 momus 를 plan-gated 로 묶어둔 것도 그래서다.
- 승인 편향이 명시적인 건 드물게 좋은 설계다. 리뷰어가 완벽주의로 흐르는 걸 막는다.
  우리가 리뷰를 위임할 때 참고할 만하다.
- 다만 이건 "계획서 검수"지 "코드·산출물 검수"가 아니다. 우리가 필요한 건 후자에 가깝다.

## 결정할 것

1. **librarian** — 우리에게 대응물이 없는 유일한 자리다. 켤지, 아니면 웹 조사 계약을
   우리 프롬프트에 직접 쓸지.
2. **explore** — 우리 teammate 로도 되는 일이다. 출력 형식이 우리와 충돌한다.
   병렬 발사와 절대경로 요구만 가져오는 편이 나을 수 있다.
3. **metis / momus** — ULW 계획 워크플로에 묶여 있다. 그 워크플로를 쓸 게 아니면
   켜도 헛돈다. 안의 좋은 문단(AI-Slop, 승인 편향)만 발췌하는 쪽을 권한다.
4. 무엇을 켜든 **모델을 명시**해야 한다. 정의에 `model` 이 없어서 안 정하면 무엇으로 도는지
   모른다.
